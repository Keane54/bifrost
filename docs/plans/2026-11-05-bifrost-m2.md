# Bifrost M2 (Window manager) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Panels inside the one Bifrost window that you can move, resize, snap, stack, minimise, lock and fade, with position memory, named layouts and three display modes.

**Architecture:** Pure TypeScript modules hold all window manager logic: geometry (`wm/geometry.ts`), state (`wm/state.ts`, a reducer) and layouts (`wm/layout.ts`). React components only connect pointer events to these modules. The main process stores the UI state as opaque JSON, owns the display mode and builds the app menu.

**Tech Stack:** Electron 44, React 19 (useReducer and context, no Zustand), Tailwind CSS v4.3.3 with `@tailwindcss/vite`, Biome, Vitest.

**Spec:** `docs/specs/2026-11-04-bifrost-design.md` (sections 5.2, 5.3, 8.1, 8.2, 8.10, 9.3, 9.4, 9.7, 12, 14.0).

## Global Constraints

- Write all prose, comments and commit bodies in ASD-STE100. Never use the em dash. Wrap commit body lines at 100 characters. Use Conventional Commits.
- Write ESM TypeScript only. The only CommonJS file is the preload build output.
- Add only `tailwindcss` 4.3.3 and `@tailwindcss/vite` 4.3.3 (exact versions, devDependencies). The feature that needs them: all styles (spec 14.0). Add no other library. No Zustand, no drag library, no UI kit.
- Context isolation and the sandbox stay on. The renderer uses only `window.bifrost`. Each new IPC handler that writes a file or changes the window checks the sender page with the existing `fromPage` helper.
- Panel IDs are fixed: `overview:<n>` (n ≥ 1), `selected-item`, `integration`, `chat:<session-id>` (spec 8.1).
- Snap distance: 8 pixels (`SNAP_DISTANCE = 8`). A panel snaps at 8 pixels or less (spec 8.1, 12).
- Opacity: 30% to 100% (spec 8.1).
- A panel without a saved position opens in the centre. A saved position outside the window moves into the window (spec 8.1).
- At start, Bifrost restores the last layout (spec 8.1).
- Display modes: Window (default), Borderless (`setSimpleFullScreen`), Fullscreen (`setFullScreen`). Bifrost keeps the last mode. Cmd+Ctrl+F toggles Fullscreen. Borderless has no default key (spec 8.1, 9.4).
- Do not bind the shortcuts that macOS keeps (spec 9.7). Cmd+W closes the focused panel, not the Bifrost window (spec 9.4).
- One CSS file holds all colour tokens: `src/renderer/src/styles/app.css`. Yellow, red and grey mean the yellow box, the red box and a parked session only (spec 8.10).
- Bifrost uses its own colours, icons and fonts. Do not copy EVE assets or the styles of other projects.
- Build each `className` with `cx()`. Do not build a `className` with a template literal (the Biome `useSortedClasses` fix breaks template literals).
- Tests live in `test/**` and run in the Vitest node environment. The pure modules carry the logic and the tests. React components get no unit tests; Task 8 checks them in the running app.
- Keep `main.tsx` without StrictMode (a second mount starts a second attach).
- `pnpm test`, `pnpm typecheck` and `pnpm check` pass after each task.

## Review Focus

1. The Bifrost window gets smaller, or the display mode changes, after you put panels near the right or bottom edge. Expected: every panel stays fully inside the window. Owner: Task 3 (`bounds` tests).
2. `ui-state.json` comes from a larger screen, or it is damaged. Expected: panels move into the window; a damaged file gives the default layout; a file that Bifrost cannot read is never overwritten. Owner: Task 4.
3. You release the mouse button outside the Bifrost window during a drag, or macOS cancels the pointer. Expected: the drag ends and the panel stays where it was last drawn. Owner: Task 5 (`pointercancel` and `lostpointercapture` end the drag).
4. You leave native full screen with the green button or Esc. Expected: the View menu and the saved mode change to the real mode. Owner: Task 7 (`sync` tests).
5. You close one tab of a stack, then open that panel again. Expected: the other tabs stay; the panel opens at the position of the stack when you closed it. Closing the last tab removes the frame. Owner: Task 3.

### Task 2: Geometry with snap

**Files:**
- Create: `src/renderer/src/wm/geometry.ts`
- Test: `test/renderer/wm/geometry.test.ts`

**Interfaces:**
- Produces:
  - `interface Rect { x: number; y: number; w: number; h: number }`, `interface Size { w: number; h: number }`, `interface Point { x: number; y: number }`
  - `type Edge = 'n' | 's' | 'e' | 'w' | 'ne' | 'nw' | 'se' | 'sw'`
  - `interface Guide { axis: 'x' | 'y'; at: number }` (a vertical line at x, or a horizontal line at y)
  - `const SNAP_DISTANCE = 8`, `const MIN_SIZE: Size = { w: 200, h: 120 }`, `const TITLE_H = 28`
  - `clampRect(r: Rect, bounds: Size, min?: Size): Rect`
  - `centreRect(size: Size, bounds: Size): Rect`
  - `moveRect(start: Rect, dx: number, dy: number, others: Rect[], bounds: Size, snap?: number): { rect: Rect; guides: Guide[] }`
  - `resizeRect(start: Rect, edge: Edge, dx: number, dy: number, others: Rect[], bounds: Size, snap?: number, min?: Size): { rect: Rect; guides: Guide[] }`
  - `contains(r: Rect, p: Point): boolean`, `titleBar(r: Rect): Rect` (the top `TITLE_H` pixels)

Rules:
- All results are whole numbers (`Math.round`).
- `clampRect`: first shrink the rect to fit `bounds` (not below `min`), then move it fully inside. If `bounds` is smaller than `min`, use `bounds`.
- `moveRect`: the candidate x lines are `0`, `bounds.w`, and the left and right edges of each other rect whose y range overlaps the moved rect's y range, with `snap` pixels of tolerance. The left edge and the right edge of the moved rect both try each line. The smallest distance at or below `snap` wins. On a tie, the bounds line wins, then the first other rect. The y axis uses the same rule. After the snap, clamp into `bounds`. A guide comes back for each axis that snapped.
- `resizeRect`: only the edges named by `edge` move and snap. The opposite edges stay fixed. Apply `min` after the snap. An edge cannot pass the bounds.

### Task 3: Window manager state

**Files:**
- Create: `src/renderer/src/wm/state.ts`
- Modify: `docs/specs/2026-11-04-bifrost-design.md` (5.2 and the 14.0 Zustand row)
- Test: `test/renderer/wm/state.test.ts`

**Interfaces:**
- Consumes: `Rect`, `Size`, `clampRect`, `centreRect` (Task 2).
- Produces:
  - `type PanelKind = 'overview' | 'selected-item' | 'integration' | 'chat'`
  - `panelKind(panelId: string): PanelKind | null`. Valid IDs: `overview:<n>` with n a whole number from 1 to 99, `selected-item`, `integration`, `chat:<uuid>`. All others give `null`.
  - `const DEFAULT_SIZES: Record<PanelKind, Size>`: overview `{w:760,h:360}`, selected-item `{w:360,h:300}`, integration `{w:520,h:320}`, chat `{w:720,h:480}`.
  - `interface Frame { id: string; panels: string[]; active: string; rect: Rect; minimised: boolean; locked: boolean; opacity: number }`
  - `interface WmState { frames: Frame[]; memory: Record<string, Rect>; bounds: Size; nextFrame: number }`. `frames` is in z-order: the last frame is on top.
  - `type WmAction`:
    - `{ type: 'open'; panelId: string }`
    - `{ type: 'close'; panelId: string }`
    - `{ type: 'closeActive' }` (close the active panel of the top frame that is not minimised)
    - `{ type: 'focus'; frameId: string }`
    - `{ type: 'setRect'; frameId: string; rect: Rect }` (move and resize)
    - `{ type: 'stack'; frameId: string; targetId: string }`
    - `{ type: 'unstack'; panelId: string; rect: Rect }`
    - `{ type: 'activate'; panelId: string }`
    - `{ type: 'minimise'; frameId: string }`, `{ type: 'restore'; frameId: string }`
    - `{ type: 'lock'; frameId: string; locked: boolean }`
    - `{ type: 'opacity'; frameId: string; opacity: number }`
    - `{ type: 'bounds'; bounds: Size }`
    - `{ type: 'load'; frames: Omit<Frame, 'id'>[]; memory: Record<string, Rect> }`
  - `wmReducer(state: WmState, action: WmAction): WmState`
  - `initialState(bounds: Size): WmState` (no frames, empty memory, `nextFrame: 1`)
  - `frameOf(state: WmState, panelId: string): Frame | undefined`
  - `topFrame(state: WmState): Frame | undefined` (the last frame that is not minimised)

Rules:
- A new frame gets the ID `f<nextFrame>`. Then `nextFrame` goes up by 1. The UI can know the ID of the next new frame from `state.nextFrame`.
- `open`: an open panel → activate its tab, restore its frame, and move the frame to the top. A closed panel with a valid ID → a new frame on top, at `memory[panelId]` clamped into `bounds`, or else at `centreRect(DEFAULT_SIZES[kind])`. An invalid ID → no change.
- `close`: write the frame rect to `memory[panelId]`. Remove the panel from its frame. The frame with no panels goes away. Else the active panel becomes the tab to the left, or the first tab.
- `setRect`: clamp into `bounds`. No change for a locked or minimised frame.
- `stack`: append the source panels to the target. The target's active panel becomes the source's active panel. Remove the source frame. Move the target to the top. No change if the source is the target, if either is minimised, or if the source is locked.
- `unstack`: only for a frame with two or more panels that is not locked. Write the old frame rect to `memory[panelId]`. Remove the panel from the old frame (the active rule of `close`). Add a new frame on top with the clamped `rect`, the old frame's opacity, `locked: false`.
- `minimise` and `restore` set `minimised`. `restore` also moves the frame to the top.
- `opacity`: clamp to 0.3 to 1, round to 2 decimals.
- `bounds`: set `bounds` only. Each frame keeps the rect that the user set.
- `load`: replace all frames (new IDs from `nextFrame`), replace `memory`, keep each rect as saved. Drop frames whose panels are all invalid or repeat a panel that an earlier frame has. A frame whose `active` is not in its `panels` gets its first panel as active.
- `shownRect(rect, bounds)` in `geometry.ts` clamps a frame rect into `bounds` with `MIN_SIZE`. The screen, the hit tests, the snap lines, the guides and the start of a drag or resize use the shown rect. A save writes the frame rect, not the shown rect.
- The reducer never mutates its input. A no-change action returns the same object.

**Files:**

**Interfaces:**
- Consumes: `Frame`, `WmState`, `panelKind`, `Rect` (Tasks 2 and 3).
- Produces (renderer, `layout.ts`):
  - `interface LayoutSnapshot { frames: Omit<Frame, 'id'>[]; memory: Record<string, Rect> }`
  - `interface UiStore { version: 1; current: LayoutSnapshot | null; layouts: { name: string; snapshot: LayoutSnapshot }[] }`
  - `const EMPTY_STORE: UiStore`, `const MAX_LAYOUTS = 20`, `const MAX_NAME = 40`
  - `toSnapshot(state: WmState): LayoutSnapshot`
  - `parseUiStore(data: unknown): UiStore`
  - `saveLayout(store: UiStore, name: string, snapshot: LayoutSnapshot): UiStore`
  - `deleteLayout(store: UiStore, name: string): UiStore`
- Produces (main):
  - `writeJsonAtomic(file: string, data: unknown): Promise<void>` (mkdir, random temp name with flag `wx` and mode 0600, rename, remove the temp file on failure)
  - `readJsonFile(file: string): Promise<{ ok: true; data: unknown } | { ok: false; missing: boolean }>`: ENOENT gives `{ok:false, missing:true}`; bad JSON gives `{ok:false, missing:false}`; other errors reject.
  - `openUiStore(file: string, log?): Promise<{ data: unknown; save(data: unknown): Promise<void> }>`: a missing file gives `data: null` and a working save. Bad JSON gives `data: null` and a working save (the renderer then writes a good file). A read error gives `data: null` and a save that does nothing.
  - `const MAX_UI_BYTES = 1_000_000`. `save` rejects data that is not a plain object or whose JSON is larger.
- Produces (API): `ui: { load(): Promise<unknown>; save(data: unknown): Promise<void> }` on `BifrostApi`. IPC channels `ui:load` and `ui:save`. Both use `fromPage`. The file is `ui-state.json` in `app.getPath('userData')`.

Rules for `parseUiStore`:
- Data that is not an object, or with `version` not 1, gives `EMPTY_STORE`.
- A rect needs four finite numbers and `w`, `h` > 0. Else drop the item that holds it.
- A frame needs a non-empty `panels` array of valid panel IDs (drop invalid IDs), booleans for `minimised` and `locked` (default false), and `opacity` (default 1, clamp 0.3 to 1).
- Memory keeps only valid panel IDs with valid rects.
- Layout names are trimmed strings of 1 to `MAX_NAME` characters. Keep the first `MAX_LAYOUTS` layouts. A repeated name keeps the first.
- `saveLayout`: trim the name; refuse (return the same store) an empty or too long name; replace a layout with the same name in place; else append; refuse a new name when the store has `MAX_LAYOUTS`.

### Task 7: Display modes and the app menu

**Files:**
- Create: `src/main/window/display-mode.ts`, `src/main/window/window-state.ts`, `src/main/menu.ts`
- Modify: `src/main/index.ts`, `src/main/ipc.ts`, `src/shared/api.ts`, `src/preload/index.ts`, `src/renderer/src/wm/WindowManager.tsx` (close the active panel on the menu event)

**Interfaces:**
- Consumes: `writeJsonAtomic`, `readJsonFile` (Task 4); `closeActive` action (Task 3).
- Produces:
  - `type DisplayMode = 'window' | 'borderless' | 'fullscreen'` (in `src/shared/types.ts`)
  - `interface ModeWindow { isFullScreen(): boolean; setFullScreen(on: boolean): void; isSimpleFullScreen(): boolean; setSimpleFullScreen(on: boolean): void; once(event: 'enter-full-screen' | 'leave-full-screen', cb: () => void): void }`
  - `createModeController(win: ModeWindow, onChange: (mode: DisplayMode) => void, waitMs?: number): { get(): DisplayMode; set(mode: DisplayMode): Promise<void>; toggleFullscreen(): Promise<void>; sync(): void }`
  - `interface Bounds { x: number; y: number; width: number; height: number }`
  - `interface WindowState { mode: DisplayMode; bounds: Bounds | null }`
  - `parseWindowState(data: unknown): WindowState`
  - `restoreBounds(saved: Bounds | null, workAreas: Bounds[], fallback: { width: number; height: number }): Partial<Bounds> & { width: number; height: number }`
  - `buildMenuTemplate(opts: { mode: DisplayMode; isDev: boolean; onMode(mode: DisplayMode): void; onToggleFullscreen(): void; onClosePanel(): void }): MenuItemConstructorOptions[]` (type-only import from `electron`)
  - API: `display: { get(): Promise<DisplayMode>; set(mode: DisplayMode): Promise<void>; onChange(cb: (mode: DisplayMode) => void): () => void }` and `wm: { onClosePanel(cb: () => void): () => void }`. Channels `display:get`, `display:set` (with `fromPage`; refuse a value that is not a mode), `display:changed`, `wm:close-panel`.

Rules for the mode controller:
- `get` reads the window: fullscreen if `isFullScreen()`, else borderless if `isSimpleFullScreen()`, else window.
- `set(mode)` with the current mode does nothing.
- Leave Fullscreen: `setFullScreen(false)`, then wait for `leave-full-screen`, or `waitMs` (default 3000).
- To Window: leave Fullscreen or Borderless (`setSimpleFullScreen(false)`).
- To Borderless: leave Fullscreen first if necessary, then `setSimpleFullScreen(true)`.
- To Fullscreen: `setSimpleFullScreen(false)` if borderless, then `setFullScreen(true)` and wait for `enter-full-screen` or `waitMs`.
- Calls run one after the other. A second `set` starts after the first ends.
- `toggleFullscreen`: from Fullscreen, go back to the mode before Fullscreen (Window if unknown). Else go to Fullscreen.
- `onChange` runs once after each change of the real mode. `sync()` (for the window events `enter-full-screen` and `leave-full-screen`) calls `onChange` only when `get()` differs from the last mode.

Rules for the window state:
- `parseWindowState`: a bad value gives `{ mode: 'window', bounds: null }`. Bounds need four finite numbers, width ≥ 400 and height ≥ 300.
- `restoreBounds`: use `saved` if a 100 × 40 pixel part of its top edge area is inside one work area. Else give only `fallback` (Electron centres the window).
- File: `window-state.json` in userData. Save the mode on each change. Save `getNormalBounds()` on `close`, and on `resize` and `move` with a 500 ms debounce.

Rules for the menu:
- App menu: About, Hide (Cmd+H), Hide Others, Show All, Quit (Cmd+Q), with Electron roles.
- Edit menu: Undo, Redo, Cut, Copy, Paste, Select All, with Electron roles. Text boxes need these items on macOS.
- View menu: radio items Window, Borderless and Fullscreen. The item of the current mode is checked. Fullscreen has the accelerator `Ctrl+Cmd+F` and calls `onToggleFullscreen`. Window and Borderless call `onMode`. In development only: Reload and Toggle Developer Tools.
- Window menu: Close Panel (`Cmd+W`, calls `onClosePanel`), Minimize (role), Zoom (role). No item has the role `close`.
- Rebuild the menu after each mode change, so the radio items show the real mode.
- `index.ts`: create the window with `restoreBounds`. After `ready-to-show`, apply the saved mode. Send `display:changed` to the renderer on each change.
