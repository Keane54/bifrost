# Bifrost M0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Set up the Bifrost Electron app and answer the 12 M0 questions about `claude attach` with a test harness.

**Architecture:** The main process finds the `claude` binary, reads `claude agents --json` and runs `claude` in node-pty processes. A typed preload API gives these functions to the renderer. A temporary React harness shows the sessions and xterm.js views. The harness is the tool for the M0 experiments. Later milestones keep the main-process code and the terminal view.

**Tech Stack:** Electron, electron-vite, React, TypeScript, node-pty, `@xterm/xterm`, `@xterm/addon-fit`, `@xterm/addon-webgl`, Vitest, pnpm.

**Spec:** `docs/specs/2026-11-04-bifrost-design.md`. Read sections 4, 5, 9.2, 14.1 and 17 before you start.

**Later plans:** M1 to M5 each get a separate plan. Claude writes them after the user reviews the M0 findings (Task 8).

## Global Constraints

- macOS only. This Mac has Node 26.8.1, pnpm 12.3.4 and Claude Code 2.1.318.
- `package.json` has `"name": "bifrost"`, `"productName": "Bifrost"`, `"private": true` and `"license": "UNLICENSED"`.
- Use exact dependency versions. Do not use `^` or `~`.
- The repository has no remote. Commits stay local.
- Write all documents, code comments and commit message bodies in ASD-STE100. Never use the em dash.
- Use Conventional Commits for commit subjects.
- Context isolation is on. Node integration is off. The renderer gets Node functions only through the preload API.
- The main process spawns only the resolved `claude` binary in a PTY. The renderer never supplies a program path.
- Do not change `~/.claude/settings.json` in M0.
- **Test sessions:** each test session has a name that starts with `bifrost-test-`. It uses `--model haiku`. Its directory is `.m0-sandbox/` in the repository.
- **Safety:** never send input, a signal, `claude stop` or `claude rm` to a session whose name does not start with `bifrost-test-`. The user has real sessions open on this Mac.

## Review Focus

1. **Bifrost starts from Finder or the Dock.** A GUI app does not get the shell PATH, so it cannot find `claude`. Bifrost must find `claude` through a login shell. Task 2 tests `resolveClaudePath`.
2. **`claude agents --json` prints extra text or no text.** An update notice before the JSON, or empty output, must not stop Bifrost. Bifrost must show an error and an empty list. Task 2 tests `parseAgents`.
3. **The attach process ends at once.** A bad session ID makes `claude attach` exit. The view must show the exit and must not stop. Task 3 tests the `exit` event.
4. **A hidden or minimised view resizes to 0 columns.** node-pty fails with a size of 0. Bifrost must ignore that resize. Task 3 tests `resize`.
5. **A signal goes to a session that is not a test session.** A wrong PID can end one of the user's real sessions. The main process must refuse it. Task 4 tests `canSignal`.

```ts
// src/main/pty/pty-manager.ts
export interface PtyProcess {
  pid: number
  write(data: string): void
  resize(cols: number, rows: number): void
  kill(signal?: string): void
  onData(cb: (chunk: string) => void): void
  onExit(cb: (e: { exitCode: number; signal?: number }) => void): void
}
export type SpawnFn = (file: string, args: string[],
  opts: { cwd: string; cols: number; rows: number; env: Record<string, string> }) => PtyProcess
export class PtyManager {
  constructor(spawn: SpawnFn, file: string)
  open(viewId: string, args: string[], opts: { cwd: string; cols: number; rows: number }): number  // returns the PID
  write(viewId: string, data: string): boolean
  resize(viewId: string, cols: number, rows: number): void
  close(viewId: string, signal?: string): void        // default signal 'SIGHUP'
  onData(cb: (viewId: string, chunk: string) => void): void
  onExit(cb: (viewId: string, exitCode: number, signal?: number) => void): void
}

// src/shared/api.ts - the type of window.bifrost
export interface BifrostApi {
  claudePath(): Promise<string | null>
  agents: { list(all?: boolean): Promise<AgentList> }
  pty: {
    open(viewId: string, args: string[], opts: { cwd: string; cols: number; rows: number }): Promise<number>
    write(viewId: string, data: string): Promise<boolean>
    resize(viewId: string, cols: number, rows: number): Promise<void>
    close(viewId: string, signal?: string): Promise<void>
    onData(cb: (viewId: string, chunk: string) => void): () => void   // returns an unsubscribe function
    onExit(cb: (viewId: string, exitCode: number, signal?: number) => void): () => void
  }
}
```

IPC channels: `claude:path`, `agents:list`, `pty:open`, `pty:write`, `pty:resize`, `pty:close` (invoke). `pty:data` and `pty:exit` (main to renderer).
