# Bifrost M3 (Core panels) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** You can select, open and use sessions: the Overview with the EVE layout, the Selected Item panel, the right-click menu, and chat windows with the size rule.

**Architecture:** Pure TypeScript modules hold the logic: the Overview tabs, filters, sort and config (`overview/`), the action model (`actions/action-model.ts`), and the chat size rule and the agent view detection (`chat/`). React components connect these modules to the M2 window manager and the registry. Chat terminals live outside React in one manager. The manager keys them by the open chat panels, so a stack, a tab change or a minimise does not restart the attach. The main process stores the priorities in `registry.json` and runs Open project and Copy session ID.

**Tech Stack:** Electron 44, React 19, Tailwind CSS 4.3.3, Base UI 1.9.0, TanStack Table 9.3.1, lucide-react 1.61.0, xterm.js 6 with the fit and WebGL addons, node-pty, Biome, Vitest.

**Spec:** `docs/specs/2026-11-04-bifrost-design.md` (sections 6, 7, 8.3, 8.4, 8.5, 9.1, 9.3, 9.5, 12, 13, 14.0, 18, 19, 20).

3. A row changes after you open its menu or select it: it parks, it goes away, or it becomes external. Expected: the action checks the current row again and has no effect, or the main process refuses it. Owner: Task 5 (`actionStateFor` with a missing row), Task 2 (`setPriority` refuses an unknown session), Task 3 (`openProject` and `copySessionId` refuse an unknown session).

Expected: defaults for the bad parts. The layouts and the session names stay. Owner: Task 2 (`loadStore` tests) and Task 4 (`parseOverviewConfig` and `parseUiStore` tests).

| D7 | The "focused chat window" is the active chat panel of the top frame that is not minimised. | M2 moves a frame to the top on each pointer down. |
| D8 | The zoom of an unfocused chat window never goes above 1. A transparent overlay covers a zoomed, unfocused terminal, because xterm.js mouse cells are wrong under a CSS scale. | A small terminal stays sharp. The first click only focuses. |

| D10 | The agent view needs its footer on one of the last 3 non-empty screen lines and its counts line on the screen. Input stops at once. A maximum of 3 attaches in 60 seconds. | No false match on quoted text. No attach loop. |
| D11 | Copy session ID uses the Electron clipboard in the main process. | It does not depend on a renderer permission. |
| D12 | Open project runs `/usr/bin/open -a <app bundle path> <cwd>`. The list is Finder, VS Code, Zed, and the first installed of Warp, Ghostty, iTerm2, Terminal (spec 12) until Settings exist (M5). | The main process finds the cwd and the app. The renderer sends only IDs. |

| D14 | Size rule: Task 1 rules "yes" or "no". Task 10 builds the design that works for both answers (the "no" fallback is the case with no session size). Task 11 adds the session size source only for "yes". | The plan runs without a stop for the user. |

Rules:
- `poke` starts one read `debounceMs` after the last poke of that view. One read runs at a time for each view. A read for a view with no pid does nothing.
- `emit` runs only when the size differs from the last size of that view. `forget` removes the view and its last size.
- `ipc.ts`: in the `PtyManager.onData` callback, a `chat:` view whose chunk contains `\x1b[2J` (the full redraw after a resize, M0 question 1) calls `poke`. A resolved `pty:open` of a `chat:` view calls `poke`. `pty:close` and the exit of a view call `forget`. `pidOf` finds the owned row whose `sessionId` is the part after `chat:`.
- Renderer: `ChatTerminals` subscribes to `pty.onSize` and calls `get(id)?.setSessionSize(size)`. An unfocused terminal calls `pty.sessionSize(sessionId)` before its first `pty.open` and gives the result to `openSize`.
