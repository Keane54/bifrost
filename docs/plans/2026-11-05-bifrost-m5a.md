# Bifrost M5a (Finish, part 1: settings, keys, labels, alerts) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Settings that the main process keeps, the label toggle, the setup dialog and Settings > Live details, the full key map of spec 9.4 with hold-key-and-click and a key editor, and the three alerts (row flash, macOS notification, sound).

**Architecture:** Pure TypeScript modules hold the rules: the key map (`src/shared/keys.ts`), the settings model (`src/shared/settings.ts`), the key commands, the hold gate and the focus zones (`src/renderer/src/keys/`), the Live details notice and the key editor model (`src/renderer/src/settings/`), and the alert rules (`src/main/alerts/alert-monitor.ts`). The main process owns `settings.json` and applies the settings that it needs. The renderer registers each key with TanStack Hotkeys in the capture phase and decides with `keyAllowed` if Bifrost takes the key or the chat window gets it.

**Tech Stack:** Electron 44, React 19, Tailwind CSS 4.3.3, Base UI 1.9.0, lucide-react 1.61.0, `@tanstack/react-hotkeys` 0.16.0 (new), xterm.js 6, node-pty, Biome, Vitest.

**Spec:** `docs/specs/2026-11-04-bifrost-design.md`

M5 has two plans. This plan (M5a) has 9 tasks and its own exit check (Task 9). The second plan (`2026-11-05-bifrost-m5b.md`) adds Show Info, the Event log, the Usage HUD, the Service status panel, the theme check, the smoke test and the DMG.

**Order:** This plan starts after the Live details plan (`docs/plans/2026-11-05-bifrost-live-mod.md`) merges into `main`. M4 and the tab colours are on `main` (2231a0a). Read the merged code for the exact form of each name.

## Review Focus

1. The user types in a chat window: `o`, `1`, Esc, Backspace, Tab, arrow keys, Ctrl+C or Ctrl+R. Expected: each key goes to the Claude Code TUI. Only a binding with Mod acts in Bifrost. Owner: Task 1 (`keyAllowed follows spec 9.3` with the chat zone) and Task 6 (the callback returns before `preventDefault` when the key is not allowed).
2. The user holds O and clicks a row that is not the selected row. Expected: the clicked row opens. The selected session does not open at the keyup. Two held hold keys give a normal click. Owner: Task 5 (`HoldGate` tests).
3. `settings.json` is damaged, comes from a later version with unknown keys, or holds values out of range (poll 0, escalation -5, font size 200, a slash command with a line break, a key for an unknown slot). Expected: the default for each bad value, and the other values stay. A file that Bifrost cannot read is never overwritten. Owner: Task 2 (`parseSettings` and `openSettingsStore` tests).
4. Bifrost wakes after Maintenance Sleep (M1 F1) and 8 yellow boxes escalate to red in one tick. Expected: one summary notification and one sound, not 8. Owner: Task 8 (`more than 3 new boxes give one summary notification`, `the sound plays at most once each 2 seconds`).
5. The packaged app and the menu take keys from the renderer. The electron-toolkit optimizer blocks Cmd+R and Cmd+Shift+R in production. The dev Reload item uses Cmd+R. Expected: Resume and Resume all work in the DMG build and in development. Owner: Task 6 (`no menu accelerator equals a renderer key of the default map` and the optimizer removal).
6. A check clicks Install or Remove of Live details in a test home. Expected: the `claude plugin` commands and the old-hook removal change only files under the test home. The user's `~/.claude/settings.json`, `~/.claude/plugins/installed_plugins.json` and `~/.claude/plugins/known_marketplaces.json` keep their SHA-256. Owner: Task 4 (`pluginEnv gives the test home to plugin commands only`) and Task 9 Step 3.

### Task 1: Key map model

**Files:**
- Create: `src/shared/keys.ts`
- Test: `test/shared/keys.test.ts`

**Interfaces:**
- Produces (`src/shared/keys.ts`, no imports from a library):
  - `type KeyCommandId = 'new-session' | 'select-row' | 'select-prev' | 'select-next' | 'focus-overview' | 'open' | 'send-message' | 'run-slash' | 'interrupt' | 'rename' | 'show-info' | 'copy-id' | 'open-project' | 'open-in-terminal' | 'take-control' | 'resume' | 'resume-all' | 'set-priority' | 'close-panel' | 'stop' | 'delete' | 'prev-stack-tab' | 'next-stack-tab' | 'next-overview-tab' | 'prev-overview-tab' | 'load-layout' | 'save-layout' | 'event-log' | 'usage-hud' | 'settings' | 'toggle-fullscreen' | 'escape'`
  - `type SlotGroup = 'always' | 'single' | 'hold'` (the three tables of spec 9.4)
  - `interface KeySlot { id: string; command: KeyCommandId; arg?: number; group: SlotGroup; default: string; menu?: true }`
  - `const KEY_SLOTS: readonly KeySlot[]` and `slotById(id: string): KeySlot | undefined`
  - `type CustomKeys = Record<string, string | null>` (changed slots only) and `type KeyMap = Record<string, string | null>` (all slots)
  - `interface Chord { mod: boolean; ctrl: boolean; alt: boolean; shift: boolean; key: string }`
  - `parseBinding(text: string): Chord | null`, `formatBinding(chord: Chord): string`, `canonicalBinding(text: string): string | null`

Rules:
- `parseBinding`: split on `+`. Modifier tokens, without case: `Mod`, `Cmd`, `Command`, `Meta` give `mod`. `Control`, `Ctrl` give `ctrl`. `Alt`, `Option` give `alt`. `Shift` gives `shift`. A modifier can come only one time. Exactly one key token: a letter (stored upper case), a digit, one of `ArrowUp ArrowDown ArrowLeft ArrowRight Enter Escape Tab Backspace Delete Space Home End PageUp PageDown F1`..`F12`, or one character of `` / . , [ ] ; ' ` - = \ ``. Aliases: `Esc` is `Escape`, `Return` is `Enter`, `Up`, `Down`, `Left`, `Right` are the arrow keys. All other input gives null.
- `formatBinding`: the modifiers in the order Mod, Control, Alt, Shift, then the key, joined with `+`. `canonicalBinding` is `parseBinding` then `formatBinding`.
- `recordedToBinding`: change `[KeyA]` to `[KeyZ]` to the letter, `[Digit0]` to `[Digit9]` to the digit, and `[Slash] [Period] [Comma] [BracketLeft] [BracketRight] [Semicolon] [Quote] [Backquote] [Minus] [Equal] [Backslash]` to their characters. Then `canonicalBinding`.
- `reservedReason`: `REASON_MAC_KEEPS` for `Mod+Tab`, `Mod+Space`, `Mod+H`, `Mod+M`, `Mod+Q`, `Mod+Alt+Escape`, `Mod+Shift+3`, `Mod+Shift+4`, `Mod+Shift+5`, `Mod+Shift+Q`, `Mod+Shift+/`, `Mod+Control+Q`, `Control+Space` (spec 9.7). `REASON_MENU_KEEPS` for `Mod+Z`, `Mod+Shift+Z`, `Mod+X`, `Mod+C`, `Mod+V`, `Mod+A`, `Mod+Alt+H` (the M2 Edit and app menus), `Mod+=` and `Mod+-` (the View menu Zoom In and Zoom Out of the Interface scale, D7). Compare canonical forms.
- `checkBinding` (the first failure gives the result): an unknown slot or a binding that does not parse gives `REASON_BAD_KEY`. A hold slot needs one letter or one digit with no modifier, else `REASON_HOLD_FORM`. A slot that is not a hold slot refuses a reserved binding with its reason. A conflict is another slot of the same class with the same canonical binding. The two classes are hold slots and all other slots. The slot itself does not count. A conflict gives `{ ok: false, reason: 'conflict', conflict: <other slot ID> }`. Else `{ ok: true, binding: <canonical> }`.
- `effectiveKeys`: for each slot, the value of `custom[id]` when the key exists (a string or null), else the default.
- `parseCustomKeys`: data that is not a plain object gives `{}`. Keep an entry only for a known slot ID, with the value null, or a string that `checkBinding` accepts against the default map, or that fails only with `conflict`. Store the canonical form. Conflicts in a file stay; `activeBindings` handles them.
- `setSlotKey`: a binding equal to the default removes the entry. Else set it (null means no key). `resetSlotKey` removes the entry. Both return the same object when nothing changes.
- `keyConflicts`: each pair `[a, b]` of slots of the same class with the same non-null binding, `a` before `b` in `KEY_SLOTS` order.
- `activeBindings`: each slot with a non-null binding that is not a menu slot. When two slots of one class have the same binding, only the first in `KEY_SLOTS` order is in the list.
- `keyAllowed` (spec 9.3, D6, D27): `modal` gives false. A binding with Mod gives true. The `escape` command gives true only in `other`, `control` and `send-box`. A binding with Control and without Mod gives true in each zone except `chat`. Each other binding (a single key, or with Shift or Alt only) gives true in `other`, and in `control` when the key is not `Enter`, `Space` or `Tab`.
- `toAccelerator`: Mod becomes `Cmd`, Control becomes `Ctrl`, Alt stays `Alt`, Shift stays `Shift`. `ArrowUp` becomes `Up` (also Down, Left, Right), `Escape` becomes `Esc`, `Enter` becomes `Return`. Join with `+`.
