# Bifrost M4 (Actions) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** All actions of spec 9.1 work: the send box, Run slash command, Interrupt, Rename, Stop session, Delete session, New session, Take control, Resume, Resume all and Open in terminal. Show Info stays an M5 panel with the reason "Comes in M5".

**Architecture:** The main process runs each action that touches a session. `SessionInput` types into a session through the open chat PTY, or through a hidden attach that it opens and closes. `createSessionActions` runs the `claude` commands and the Take control signal, and waits for the registry entry. The registry keeps the Resume all candidates, forgets a deleted session and finds the terminal app of each external row. The renderer adds pure modules for the action rules, the confirmation texts, the dialog history and the New session form, and React parts for the dialogs and the send box.

**Tech Stack:** Electron 44, React 19, Tailwind CSS 4.3.3, Base UI 1.9.0 (from M3), lucide-react 1.61.0 (from M3), xterm.js 6, node-pty, Biome, Vitest. M4 adds no library.

**Spec:** `docs/specs/2026-11-04-bifrost-design.md` (sections 4, 6, 7, 8.4, 8.5, 8.9, 9.1, 9.2, 9.5, 9.6, 12, 13, 18, 19, 20).

- Write all prose, comments and commit bodies in ASD-STE100. Never use the em dash (also not in test strings: write `\u2014`). Wrap commit body lines at 100 characters. Use Conventional Commits.
- Write ESM TypeScript only.
- Add no library. Base UI (M3) gives the dialogs (`Dialog`, `AlertDialog`). lucide-react (M3) gives the icons. Electron gives `dialog.showOpenDialog`, `clipboard` and `app.getFileIcon`.
- Context isolation and the sandbox stay on. The renderer uses only `window.bifrost`. Each new IPC handler uses `fromPage` and checks each value. The renderer sends session IDs, text and the New session values. It never sends a command, a PID or a path to run. The main process checks the New session directory (absolute, an existing directory).
- The renderer can open, write, resize, close and block only `chat:<session-id>` views. Only the main process uses `send:<session-id>` views (D1).

- Bifrost never sends the ← key (spec 8.5). Bifrost never sends CR without text before it (spec 8.4). Bifrost never passes `--permission-mode bypassPermissions`.
- Exact texts from the spec: the send block "Answer the prompt in the chat window first." (8.4). The Take control confirmation "This ends the {terminal} process and hands control to Bifrost." (9.2). The trust error tells the user to run `claude` in the directory one time and accept the trust prompt (8.9).
- Plain labels from spec 9.1. A disabled action shows darker and faded (opacity 40%), a tooltip gives the reason, and a click on it has no effect. Show Info keeps `Comes in M5`.

- Pure logic lives in modules with Vitest tests in `test/**` (node environment). Timer tests use Vitest fake timers. React components get no unit tests. Task 10 checks them in the running app.

The user has real sessions open, also external sessions in Warp.
- `pnpm test`, `pnpm typecheck` and `pnpm check` pass after each task.

## Review Focus

1. The text holds control characters or an escape sequence, for example text copied from a terminal, or `ESC[201~` inside the text. Expected: Bifrost removes them. The text cannot end the paste early or press keys. Owner: Task 2 (`planText removes escape and control characters`).
2. A prompt opens after the click: the hidden attach waits 1.5 s, and in that time the session shows a permission prompt. Expected: Bifrost checks the box again before the first write and sends nothing. Owner: Task 2 (`send checks the red box again before the first write`).
3. Repeated clicks: two Interrupts (two Esc open the rewind menu), two Resumes (a second `claude --bg --resume` starts a copy, spec 4), or Delete while Stop runs. Expected: one action at a time for each session, a second Interrupt within 1.5 s has no effect, and Resume runs only for a parked row. Owner: Task 2 (Interrupt gap), Task 4 (lock, Resume refuses a row that is not parked), Task 6 (the running reason).
4. A send to a busy session without a chat window, or an attach that never gets quiet or ends at once. Expected: after 15 s Bifrost closes the hidden attach, writes nothing and shows the reason. No `send:` PTY stays open. Owner: Task 2.
5. The computer restarts. The background sessions end some seconds before Bifrost quits. Expected: after the next start, Resume all still offers those sessions. Owner: Task 3 (`lastActive keeps a session that parked less than 60 s ago` and `the loaded lastActive gives the resumable rows`).

Rules for `cleanText` and `planText`:
- `cleanText`: change CRLF and a lone CR to LF. Remove U+0000 to U+0008, U+000B to U+001F and U+007F to U+009F. Keep tab and LF. Use a `biome-ignore` comment for `noControlCharactersInRegex`, as `scripts/m0/lib.ts` does.
- `planText`: `t = cleanText(text).trim()`. Empty gives `REASON_EMPTY`. More than `MAX_TEXT` characters gives `REASON_TOO_LONG`. `slash` is `t.startsWith('/')`. A slash command with LF gives `REASON_SLASH_LINES`.
- A slash command in the `typed` form gives `[{ delayMs: 0, data: t }, { delayMs: 500, data: CR }]`.

Rules:

  - Else run these read-only commands, each with `{ timeoutMs: 5000 }`, in this order:

    2. `exec('git', ['-C', worktree, 'rev-parse', '--abbrev-ref', 'HEAD'])`. The trimmed text is `branch`. The text `HEAD` (a detached HEAD) gives `branch: null`.
    3. `exec('git', ['-C', repo, 'rev-parse', 'HEAD'])`. The trimmed text is the base commit.
    4. `exec('git', ['-C', worktree, 'rev-list', '--count', '<base>..HEAD'])`. The trimmed number is `unmergedCommits`.
