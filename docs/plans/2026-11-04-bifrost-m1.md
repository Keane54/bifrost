# Bifrost M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Collect live data for every local Claude Code session from the hooks, the statusline wrapper and the session list. Run the state machine with yellow and red boxes. Show the result in a debug view.

**Architecture:** Two POSIX `sh` scripts in `~/.bifrost/bin/` write hook events and statusLine JSON to files. The main process installs the scripts into `~/.claude/settings.json`, reads the files and `claude agents --json`, and merges everything in a `SessionRegistry` that runs a pure state machine. A `RegistryService` runs the timers and sends the rows to a debug view in the renderer. The M0 test harness and its guard go away.

**Tech Stack:** Electron 44, electron-vite, React 19, TypeScript, Vitest, Biome, pnpm 12, node-pty, lefthook, commitlint.

**Spec:** `docs/specs/2026-11-04-bifrost-design.md`. Read sections 2, 4, 5, 6, 7, 11, 13, 14 and 16 before you start. The M0 results are in `docs/m0-findings.md`.

**Decisions in this plan:**
- Zod: not used. The hand-written checks stay small (spec 14.0 says "decide in M1"). Task 12 records this.
- Settings UI: not in M1. M1 uses the spec defaults as constants (escalation 10 minutes, poll 2 seconds).
- The debug view uses plain CSS. Tailwind comes in M2.

## Global Constraints

- macOS only. Node 24 or later (`"engines": { "node": ">=24" }`). Claude Code minimum version 2.1.281.
- ESM TypeScript only. No CommonJS source files. Scripts run as `.ts` files directly.
- Add a library only when a feature needs it. This plan adds only `lefthook`, `@commitlint/cli` and `@commitlint/config-conventional`.
- `pnpm check`, `pnpm test`, `pnpm typecheck` and `pnpm build` exit 0 before each commit.
- Documents, code comments and commit bodies are in ASD-STE100 Simplified Technical English. Never use the em dash.
- Conventional Commit subjects. From Task 1 on, commitlint checks each commit. Wrap commit body lines at 100 characters.
- Tests never read or write the real `~/.claude/settings.json` or `~/.bifrost/`. Tests use temporary directories.
- Only Task 13 changes the real `~/.claude/settings.json`, and only when the user clicks Install.
- Bifrost runs `claude` and each PTY with the login-shell environment, without `CLAUDECODE`, `CLAUDE_CODE_*`, `TERM_PROGRAM`, `TERM_PROGRAM_VERSION`, `TERM_SESSION_ID` and `WARP_*` (spec 6.5).
- One `claude agents --json` process at a time. A maximum of 4 registry updates to the renderer each second.
- **Test sessions (Task 13 only):** name prefix `bifrost-test-`, `--model haiku`, directory `.m0-sandbox/`. Never send input, a signal, `claude stop` or `claude rm` to any other session.

## Review Focus

1. **A second install, or a Repair, when the statusLine is already the wrapper.** Bifrost must keep the saved original command. It must never save the wrapper as the "original". Task 5 tests it.
2. **`~/.claude/settings.json` is missing, empty or not valid JSON.** A missing file counts as `{}`. Text that is not valid JSON stops the install, and Bifrost changes no file. Task 6 tests it.
3. **A poll that started before a permission prompt.** Its `idle` sample must not clear the new red box. Task 8 tests it.
4. **A hook event for a session that the session list does not show yet.** Bifrost keeps the event and applies it when the session shows. Task 9 tests it.
5. **A `.zshrc` that prints text, or a login shell that fails.** Bifrost reads only the text between its markers, and falls back to its own environment. Task 3 tests it.

export function parseLoginEnvOutput(stdout: string): Record<string, string> | null

How `loadLoginEnv` works:
- It runs `exec(shell, ['-lic', script], { timeoutMs: 5000, env })`. The default shell is `opts.fallback.SHELL`, or `/bin/zsh`.
- `env` holds only `HOME`, `USER`, `LOGNAME`, `SHELL`, `LANG` and `TMPDIR` from the fallback. It also holds `BIFROST_NODE=<execPath>` and `ELECTRON_RUN_AS_NODE=1`.
- The script prints the marker, runs `"$BIFROST_NODE" -e 'process.stdout.write(JSON.stringify(process.env))'`, and prints the marker again.
- The result has no `BIFROST_NODE` and no `ELECTRON_RUN_AS_NODE`.
- On any failure the result is a copy of the string values of `fallback`.

### Task 4: Hook script and statusline wrapper

**Files:**
- Create: `src/main/integration/scripts.ts`, `test/main/integration/scripts.test.ts`

**Interfaces:**
- Produces:

```ts
export const HOOK_SCRIPT: string                                  // the full POSIX sh text
export function statuslineScript(originalCommand: string | null): string
```

Rules for both scripts (spec 6.2 and 6.3):
- The base directory is `${BIFROST_HOME:-$HOME/.bifrost}`. Tests set `BIFROST_HOME`.
- POSIX `sh` only. No `jq`, Node or Python.
- Each script starts with a short STE comment.

Hook script rules:
- `exec >/dev/null 2>&1` comes first, so the script can never write to stdout.
- It writes stdin to `events/.tmp.$$`, then moves the file to `events/<epoch seconds>-$$.json`.
- It always exits 0.

Wrapper rules:
- Read all of stdin.
- Take `session_id` only when it matches `^[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}$`.
- Write the JSON to `sessions/<id>/.status.$$`, then move it to `sessions/<id>/status.json`.
- Send the same stdin to the original command (`sh -c '<original>'`) and print its stdout without changes.
- The original command is embedded in the script at install time. Single quotes become `'\''`.
- With no original command, the wrapper prints nothing.
- The wrapper always exits 0.

**Files:**

**Interfaces:**
- Consumes: `HOOK_SCRIPT`, `statuslineScript` (Task 4). `planInstall`, `planUninstall`, `checkInstall`, `StatusLineSetting` (Task 5).
- Produces:

```ts
// src/shared/types.ts
export interface IntegrationStatus {
  installed: boolean            // no missing hooks, wrapper set, scripts present
  missingHooks: string[]
  statusLineInstalled: boolean
  scriptsPresent: boolean
  error?: string
}
export interface InstallPreview { changes: string[]; backupPath: string | null; originalCommand: string | null }

// src/main/integration/integration.ts
export interface IntegrationPaths { claudeSettings: string; bifrostHome: string }
export function defaultPaths(home: string): IntegrationPaths   // ~/.claude/settings.json, ~/.bifrost
export function previewInstall(paths: IntegrationPaths, now: Date): Promise<InstallPreview>
export function install(paths: IntegrationPaths, now: Date): Promise<IntegrationStatus>
export function uninstall(paths: IntegrationPaths, now: Date): Promise<IntegrationStatus>
export function integrationStatus(paths: IntegrationPaths): Promise<IntegrationStatus>
```

Rules (spec 11.2, 11.3):
- A missing settings file counts as `{}`.
- If the text is not valid JSON, `install` and `uninstall` reject with an error that contains "not valid JSON". No file changes.
- The backup is `<bifrostHome>/backups/settings-<YYYYMMDDTHHMMSSZ>.json` in UTC, from `now`. Bifrost makes it only if the settings file exists and the plan changes it.
- `install` writes `bin/bifrost-hook` and `bin/bifrost-statusline` with mode `0o755`.
- The wrapper embeds the command of `plan.original`, or of the saved original when the statusLine was already the wrapper.
- `install` writes `statusline-original.json` (JSON of `plan.original`, which can be `null`) only when the statusLine was not the wrapper before.
- Every file write goes to a temporary name first, then `rename`.
- `install` is also Repair. A second `install` with no changes writes no backup.

```ts
// src/shared/types.ts (add)
export type SessionState = 'working' | 'needs-you' | 'error' | 'idle' | 'parked'
export type Box = 'none' | 'yellow' | 'red'

// state-machine.ts
export interface MachineState {
  state: SessionState
  box: Box
  boxSince: number | null
  acknowledged: boolean
  redReason?: 'prompt' | 'error' | 'escalated'
  lastMessage?: string
}
export const INITIAL_STATE: MachineState   // idle, none, null, true
export const STATUS_GRACE_MS = 1000
export function onHookEvent(s: MachineState, ev: HookEvent): MachineState
export function onStatus(s: MachineState, sample: { status: string; waitingFor?: string; sampledAt: number }): MachineState
export function onTick(s: MachineState, now: number, escalationMs: number): MachineState
export function onAcknowledge(s: MachineState): MachineState
export function onParked(s: MachineState): MachineState
```

Rules (spec 6.2 and 7):

| Input | Result |
|---|---|
| `UserPromptSubmit`, `PostToolUse` | working, box none |
| `PreToolUse` with tool `AskUserQuestion`, `PermissionRequest`, `Notification` `permission_prompt` | needs-you, red, reason prompt |
| `PreToolUse` with another tool | no change |
| `Notification` `idle_prompt` | no change |
| `Stop` | needs-you, yellow, `lastMessage` from the event |
| `StopFailure` | error, red, reason error |
| `SessionStart` | idle, box none |
| `SessionEnd` | parked, box none |
| status `busy` | working, box none |
| status `waiting` with a `waitingFor` | needs-you, red, reason prompt |
| status `idle`, red reason prompt, `sampledAt > boxSince + STATUS_GRACE_MS` | idle, box none |
| status `idle`, other cases | no change, except working with no box becomes idle |
| tick: yellow and `now - boxSince >= escalationMs`, `escalationMs > 0` | red, reason escalated |

- A new box sets `boxSince` to the event time (`at`, `sampledAt` or `now`), and sets `acknowledged` to false.
- A cleared box sets `boxSince` to null.
- A parked state ignores status samples. Only `SessionStart` leaves it.
- Status samples are ignored while the state is parked.

### Task 14: Light statusline wrapper and quiet owned sessions

Run this task before Task 13. The user decided this on 2026-11-04 (spec sections 6.3 and 20).

The M1 final fix wave does this task. The wrapper there reads stdin with one `cat`, because a `read` loop in bash 3.2 reads one byte at a time (final review I1). It runs only while `~/.bifrost/active` exists (spec 6.3).

**Files:**
- Modify: `src/main/integration/scripts.ts` (`statuslineScript`)
- Create: `src/main/integration/quiet-marker.ts`
- Modify: `src/main/ipc.ts` (call the marker after each registry update)
- Test: `test/main/integration/scripts.test.ts`, `test/main/integration/quiet-marker.test.ts`

**Interfaces:**
- Consumes: `SessionRow` (`kind`, `state`, `sessionId`) from `src/shared/types.ts`. `UUID_PATTERN` from `scripts.ts`.
- Produces: `QUIET_FILE = 'quiet'`. `createQuietMarker(sessionsDir: string, writeFile?: (file: string) => Promise<void>): { mark(rows: SessionRow[]): Promise<void> }`.

Wrapper rules (spec 6.3):
- The wrapper uses shell builtins only. It starts `mv` for each run that has a valid session ID. It starts `mkdir` only when the session directory is missing. It starts `/bin/sh -c` only to run the original command.
- It reads stdin with the same `read` loop as the hook. It keeps the exact bytes, also with no newline at the end.
- It finds the first `"session_id"` key with parameter expansion. It checks the value with a `case` pattern of exactly 8-4-4-4-12 hex digits. It does not use `grep`, `sed`, `tr`, `cat`, `cp` or `mktemp`.
- It writes `sessions/<id>/.status.$$` with `printf`, then moves it to `status.json`.
- If `sessions/<id>/quiet` exists, it exits 0 and prints nothing. It does not run the original command.
- Else it runs the original command with `/bin/sh -c '<command>'`. The stdin of the original is `status.json` when the ID is valid, or `printf '%s' "$data" |` when it is not valid.
- It always exits 0.

- [ ] **Step 1: Write the failing tests**

In `scripts.test.ts`, keep the five wrapper tests. Add:
- `the wrapper works with only mv and mkdir on the PATH`: PATH has only `mv` and `mkdir` symlinks (as in the hook test). The original command is `printf 'LINE'` (a builtin). Inputs: `{"session_id":"<UUID>"}\n` and `{"a":1,\n"session_id": "<UUID>"}` (no newline at the end). Expect stdout `LINE`, code 0, and `status.json` equal to the input bytes.
- `the wrapper skips the original command for a quiet session`: create `sessions/<UUID>/quiet`. Expect stdout `''`, code 0, and a new `status.json`.
- `the wrapper takes the first session_id key`: input `{"session_id":"<UUID>","x":{"session_id":"<OTHER UUID>"}}`. Expect only `sessions/<UUID>/status.json`.
- `the wrapper refuses a session_id with extra text`: values `<UUID>x`, `x<UUID>`, and a UUID with a `g`. Expect no `sessions` directory and stdout `LINE`.

In `quiet-marker.test.ts`:
- `mark writes the quiet file for each owned session that is not parked`: rows with kinds owned/external and states idle/parked. Expect a write only for owned rows with a state other than `parked`, at `<sessionsDir>/<id>/quiet`.
- `mark writes each file one time`: two calls with the same rows give one write per session.
- `mark ignores a sessionId that is not a UUID`: `../x` gives no write.
- `mark tries again after a failed write`: the first write rejects, the second call writes.
- `mark never rejects`: a write that rejects does not reject `mark`.
