# Deliberate differences

This table lists the places where native Reviews works differently from the Electron app's
TypeScript code on purpose. That code (`src/main/reviews/`, `src/renderer/src/reviews/`, the
Reviews parts of `src/renderer/src/settings/`, and `reviews.ts`, `reviews-order.ts`,
`github-url.ts` and `invisible.ts` in `src/shared/`) is the reference for what Reviews decides, not
for how it gets there. The last column says whether you'd notice the difference in normal use, and
a row marked "for the hands-on test" is one to check by hand in the real app.

Twelve rows are ones you can see, each only in a rare case: R7 on a repository with a git submodule,
R9 when the Electron app left a request round unfinished, R10 with two copies of Bifrost, R20 after
a request round fails before it chooses its items, R21 when a signed fix meets a branch that moved,
R22 when the push or the writes of a request round stop, R24 when an approval or an action of the
Review panel doesn't go through, R25 when a draft changes on GitHub while you edit it, R27 when you
turn Watch GitHub off with the Review or Answer panel open, R28 when GitHub refuses the push or the
writes of a request round for good, and R29 when a request round would have to change a settings,
git or tool configuration file, and R34 on a PR of yours with 21 to 50 checks. R13, R14, R15,
R17, R18, R26, R30, R31, R32, R33, R35, R36, R37 and R38 are ones you'll see in everyday use of
the Reviews panel, its Review and Answer panels, the request sessions of your PRs and Settings.
All twenty-six are for the hands-on test.

A few things look different and send the same thing to GitHub and to git. Every GraphQL write
sends its values as variables in a JSON body on stdin (`gh api graphql --input -`), where most
Electron writes passed them as `-f` fields; the mutations and their inputs are the same. A
worktree goes by deleting its folder and running `git worktree prune`, where the Electron app ran
`git worktree remove --force --force` first, so no git command uses force. The fix-commit checks
read the index (`git ls-files --stage`) for a submodule or a link, where the Electron app read the
head's tree (`git ls-tree`); right after the reset of a round, the two hold the same modes. Every
git command gets `core.askPass=` and `protocol.ssh.allow=never`, where the Electron app gave them
only to the fetch and the push of a request round: the clones are partial, so any command can
download a file from GitHub, and no command may show a prompt. Only https reaches a remote
(`protocol.allow=never`), which the Electron app didn't set. Every git command, not only the ones
in a worktree, runs with a `--git-dir` that Bifrost works out from the Reviews folders, and a test
home adds a closed identity value where the Electron app took an open list of extra items.
